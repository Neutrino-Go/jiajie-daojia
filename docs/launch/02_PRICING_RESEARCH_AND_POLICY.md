# 定价研究与定价策略

## 调研方法

本次调研使用公开可访问网页和搜索结果，记录在 `price-research/competitive_pricing_matrix.csv` 和 `price-research/sources.md`。

约束：

- 不伪造价格。
- 登录、定位或动态渲染无法读取的页面记录为“无法直接获取”。
- 搜索结果、社区帖子和第三方聚合页不作为高置信长期价，只作为参考信号。
- 活动价、新客价、券后价、套餐价必须与常规价区分。

## 关键外部信号

1. 京东家政第三方聚合页可见北京地区自营日常保洁：2 小时 100 元、3 小时 150 元、4 小时 200 元，约 50 元/小时；但该页不是京东官方结算页，置信度为中。
2. e家帮公开页面显示保洁 35 元/小时，2 小时起；3 小时 105 元、4 小时 140 元、5 小时 175 元；新居开荒 10 元/㎡，50㎡起；置信度高，但城市和时效需谨慎。
3. 晨心上海家政公开页面显示上海日常保洁 2 小时 120-180 元、3 小时 180-240 元、4 小时 240-300 元，并提示临时深度保洁 50 元/小时、开荒和擦玻璃 60 元/小时；置信度高。
4. 58 到家静态页显示家庭保洁“25 元起”，同时强调透明定价、培训认证和保障；该页面更像旧版品牌介绍，不能直接作为当前成交价。
5. 宜兴雅茹家政公开开荒价格：普通开荒 5-7 元/㎡，精细开荒 8-12 元/㎡；成都保洁公司页面显示成都/北京/上海/广州/深圳等城市开荒存在明显地域差异。
6. 智联招聘上京东家政保洁师岗位显示杭州上门保洁师时薪 38-45 元，说明阿姨收入底线不宜低于 40 元/小时。

## 定价原则

正式上线定价不应继续只用固定 5% 抽成和简单城市系数。推荐改成：

平台指导价 + 城市分层 + 服务类型规则 + 优惠补贴账务 + 阿姨最低收入保护。

核心原则：

- 用户支付价可被券和拉新补贴降低。
- 阿姨到手收入不得被用户优惠直接压低。
- 平台补贴、优惠券、保险成本、保障费必须独立记账。
- 开荒保洁建议从按小时切换为按面积报价。
- 每次报价必须生成 `quoteId` 和 `priceRuleVersion`。

## 开荒保洁建议

开荒保洁建议按面积报价，不继续主推按小时。

| 城市组 | 建议价格 | 起步面积 |
| --- | ---: | ---: |
| 上海/北京/深圳/广州/杭州 | 5.9 元/㎡ | 60㎡ |
| 苏州/南京/无锡 | 5.5 元/㎡ | 60㎡ |
| 哈尔滨 | 4.9 元/㎡ | 60㎡ |

说明：

- 该价格属于上线基础价格，不应覆盖极重污、复式、别墅、外窗、高空、装修垃圾清运。
- 精细开荒应另有加价项。
- 外部公开资料显示普通开荒常见区间从 5-15 元/㎡不等，一线城市和精细开荒显著更高。

## 抽成策略

不建议继续固定 5%。

推荐动态 `platformFeeRate`：

| 服务类型 | 上线期费率 |
| --- | ---: |
| 日常保洁 | 0%-3% |
| 深度保洁 | 3%-5% |
| 家务整理/收纳 | 5%-8% |
| 开荒保洁 | 5%-8% |

账务规则：

- `cleanerIncome = cleanerBaseIncome + platformSubsidyForCleaner`。
- `couponDiscount` 只影响用户支付，不直接减少 `cleanerIncome`。
- `platformSubsidy` 计入平台成本。
- `grossMargin = customerPayAmount - cleanerIncome - protectionFee - insuranceCostAllocation - paymentFee - platformSubsidy`。

## 报价流程

1. 用户选择城市、服务类型、时长或面积。
2. 前端调用 `createPricingQuote`。
3. 云函数读取 `pricingRules` 并生成 `pricingQuotes`。
4. 前端展示 `listPrice`、`launchPrice`、`customerPayAmount`、平台保障说明。
5. 下单时传 `quoteId`。
6. `createOrder` 校验 quote 未过期、未篡改，并把报价快照写入订单。

## MVP 改造建议

v0.2.2 中实现：

- 新增 `pricingRules` 和 `pricingQuotes`。
- 前后端只使用服务端报价。
- 保留旧 `pricingSnapshot` 兼容，但新增 `priceRuleVersion`。
- 兼容旧订单时，如果没有 `quoteId`，继续读旧 `pricingSnapshot`。
